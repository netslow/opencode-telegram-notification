# Задача: OpenCode Skill для уведомления о завершении текущего запуска в Telegram

Необходимо реализовать механизм для OpenCode, позволяющий получать уведомление в Telegram после завершения обработки **текущего пользовательского промпта**.

## 1. Что именно требуется

Пользователь работает с OpenCode интерактивно.

Например, пользователь вводит:

> Реализуй авторизацию через JWT. После завершения сообщи мне в Telegram.

OpenCode начинает выполнять этот промпт:

```text
User prompt
    ↓
OpenCode
    ↓
AI reasoning
    ↓
tools / terminal / file modifications
    ↓
работа завершена
```

Когда OpenCode завершает обработку этого конкретного prompt/run, необходимо отправить уведомление в Telegram.

Например:

```text
✅ OpenCode завершил выполнение

Запрос:
Реализуй авторизацию через JWT.

Проект:
my-project
```

При этом если пользователь отправляет обычный промпт:

> Покажи текущую структуру проекта.

то Telegram-уведомление отправляться **не должно**, если в этом промпте пользователь явно не попросил уведомить его.

---

# 2. Главное требование — уведомление должно быть одноразовым

Факт необходимости уведомления относится только к **текущему запуску OpenCode**.

Например:

### Первый prompt

> Реализуй feature X и сообщи мне в Telegram, когда закончишь.

Для этого запуска:

```text
notify = true
```

После завершения:

```text
OpenCode завершил работу
        ↓
Telegram notification
        ↓
notify = consumed
```

### Следующий prompt

> Теперь покажи мне список изменённых файлов.

Для него:

```text
notify = false
```

Telegram ничего не отправляется.

---

# 3. Определение намерения пользователя

Необходимо определить, как лучше всего реализовать распознавание просьбы пользователя.

Поддержать естественные формулировки вроде:

```text
сообщи мне в Telegram, когда закончишь
уведомь меня в телеграме после завершения
напиши мне в Telegram, когда закончишь работу
send me a Telegram notification when you're done
notify me on Telegram when finished
```

Однако **не нужно самостоятельно реализовывать NLP/LLM-классификатор**, если OpenCode предоставляет более надежный способ явно активировать skill.

Исследуй возможности OpenCode и выбери наиболее надежный механизм.

Приоритет:

1. штатный механизм skills OpenCode;
2. hooks/events OpenCode;
3. другие официально поддерживаемые механизмы;
4. только если необходимо — простой parsing пользовательского запроса.

Не придумывай API OpenCode.

---

# 4. Важное различие: skill и lifecycle OpenCode

Необходимо четко разделить две задачи.

### Skill отвечает за:

* отправку сообщения в Telegram;
* конфигурацию Telegram;
* форматирование сообщения;
* обработку ошибок Telegram.

### Lifecycle integration отвечает за:

* определение начала текущего запуска;
* определение того, что пользователь попросил уведомление;
* определение завершения текущего запуска;
* передачу результата в Telegram notification.

Необходимо определить, какой реальный механизм OpenCode позволяет получить событие:

```text
user prompt submitted
```

и событие:

```text
current prompt/run completed
```

Именно **завершение текущего run**, а не завершение какой-либо бизнес-задачи, issue или Task Service.

---

# 5. Пример полного сценария

Пользователь вводит:

> Проанализируй почему падают integration tests и исправь проблему. Когда закончишь, сообщи мне в Telegram.

OpenCode начинает работу.

Во время работы может происходить:

```text
read files
run tests
edit files
run tests again
...
```

Пока OpenCode работает, Telegram ничего не отправляется.

Когда OpenCode завершает текущий run:

```text
run completed
      ↓
notification requested = true
      ↓
send Telegram message
```

Telegram:

```text
✅ OpenCode завершил работу

Запрос:
Проанализируй почему падают integration tests и исправь проблему.

Результат:
Integration tests исправлены.

Проект:
my-project
```

---

# 6. Ошибка выполнения

Если OpenCode завершил текущий run с ошибкой:

```text
❌ OpenCode завершил работу с ошибкой

Запрос:
Исправь integration tests.

Результат:
Не удалось исправить проблему.

Ошибка:
...
```

При этом Telegram является только каналом уведомления.

Ошибка Telegram **не должна влиять на OpenCode**.

Например:

```text
OpenCode run: SUCCESS
Telegram: FAILED
```

не должен превращаться в:

```text
OpenCode run: FAILED
```

---

# 7. Telegram

Использовать официальный Telegram Bot API.

Конфигурация через environment variables:

```text
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

Загружаются из .env файла, если он есть.

Опционально:

```text
TELEGRAM_ENABLED=true
TELEGRAM_TIMEOUT_SECONDS=10
```

Не хранить токен в исходном коде.

Не выводить токен в лог.

---

# 8. Telegram client

Изолировать Telegram API в отдельном компоненте.

Например концептуально:

```text
TelegramNotifier
    |
    +-- send(message)
```

Он должен:

* отправлять сообщение через Telegram Bot API;
* иметь timeout;
* обрабатывать HTTP errors;
* обрабатывать network errors;
* не раскрывать token;
* при необходимости выполнять ограниченное количество retry.

---

# 9. Формат сообщения

Сделать формат сообщения отдельным компонентом.

Минимальная информация:

```text
status
user prompt
project
result
```

При наличии соответствующей информации также:

```text
duration
working directory
model
session/run id
```

Не включать в Telegram потенциально чувствительные данные без необходимости.

Особенно не отправлять автоматически:

* содержимое `.env`;
* API tokens;
* passwords;
* private keys;
* credentials.

---

# 10. Не отправлять уведомление автоматически

Это критически важно.

Нельзя реализовать поведение:

```text
каждый завершенный OpenCode run
        ↓
Telegram
```

Нужно:

```text
prompt
   ↓
пользователь попросил Telegram?
   ├── NO  → обычное выполнение
   │
   └── YES
          ↓
       запомнить intent
          ↓
       run completed
          ↓
       Telegram
```

---

# 11. Несколько последовательных сообщений

Учесть ситуацию:

```text
Prompt 1:
Сделай X и сообщи мне в Telegram.
```

OpenCode работает.

До завершения пользователь не должен получить уведомление.

После завершения:

```text
Telegram #1
```

Затем:

```text
Prompt 2:
Сделай Y и тоже сообщи мне в Telegram.
```

После второго завершения:

```text
Telegram #2
```

Intent первого prompt не должен влиять на второй.

---

# 12. Работа с уточняющими сообщениями

Исследовать, как OpenCode представляет последовательность сообщений в рамках одной сессии.

Особенно важно различать:

```text
новый user prompt
```

и:

```text
продолжение текущего run
```

Необходимо выбрать корректную модель состояния.

Не создавать собственную сложную систему session management, если OpenCode уже предоставляет необходимый session/run identifier.

---

# 13. Тестирование

Добавить автоматические тесты для:

1. prompt без просьбы об уведомлении;
2. prompt с просьбой об уведомлении;
3. успешного завершения run;
4. завершения run с ошибкой;
5. проверки одноразовости notification intent;
6. двух последовательных prompt с разными notification intents;
7. отсутствующего Telegram token;
8. отсутствующего chat ID;
9. HTTP error Telegram API;
10. network error Telegram API;
11. проверки, что ошибка Telegram не ломает OpenCode;
12. отсутствия Telegram notification при обычном prompt.

Не использовать реальный Telegram API в unit-тестах.

---

# 14. Исследование OpenCode

Перед реализацией обязательно изучить текущую версию OpenCode.

Найти реальные механизмы:

* skills;
* hooks;
* events;
* session;
* prompt/run lifecycle;
* completion events;
* error events;
* доступ к содержимому пользовательского prompt.

Проверить документацию и исходный код OpenCode, если это необходимо.

Особенно важно найти **реальное событие завершения текущего prompt/run**.

Не использовать фиктивные API вида:

```text
onTaskCompleted()
```

если такого механизма нет в OpenCode.

# 15. Архитектура

Предложить архитектуру примерно следующего вида:

```text
                   OpenCode
                      |
                 user prompt
                      |
                      v
              Notification Intent
                 Detector
                      |
              +-------+-------+
              |               |
           notify=false    notify=true
              |               |
              |          pending intent
              |               |
              +-------+-------+
                      |
                 OpenCode run
                      |
                      v
                 run completed
                      |
                      v
             Notification Service
                      |
                      v
               TelegramNotifier
                      |
                      v
                 Telegram
```

Фактическую архитектуру адаптировать под реально доступные API OpenCode.

# 17. Definition of Done

Задача считается выполненной, если:

* [ ] найден реальный lifecycle mechanism OpenCode;
* [ ] определено начало текущего prompt/run;
* [ ] определяется просьба пользователя об уведомлении;
* [ ] notification intent привязан именно к текущему run;
* [ ] определяется завершение текущего run;
* [ ] успешное завершение отправляет Telegram;
* [ ] ошибка отправляет Telegram;
* [ ] обычный prompt не отправляет Telegram;
* [ ] notification intent не переносится на следующий prompt;
* [ ] Telegram token защищён;
* [ ] Telegram ошибки не ломают OpenCode;
* [ ] добавлены автоматические тесты;
* [ ] тесты проходят;
* [ ] добавлена документация;
* [ ] выполнен end-to-end тест.

В финальном отчёте показать:

1. какой механизм OpenCode используется;
2. как определяется просьба об уведомлении;
3. как определяется завершение run;
4. список изменённых файлов;
5. конфигурацию;
6. команды запуска тестов;
7. результат тестирования;
8. пример пользовательского prompt;
9. пример Telegram notification.
